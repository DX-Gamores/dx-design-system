<h2>Release steps (design lead)</h2>
<ol>
<li>Make the change in Figma. Update the component description: it becomes the spec.</li>
<li>Ask Claude to run the release audit (Governance page → Release health). Fix anything red.</li>
<li>Publish the library in Figma.</li>
<li>Ask Claude to <strong>re-export the code kit</strong>. That refreshes <code>figma/variables.raw.json</code>, <code>figma/styles-components.raw.json</code> and <code>figma/icons.json</code>, runs <code>npm run build:all</code>, and opens a PR titled with the new version.</li>
<li>Note the change in the Figma changelog and in the PR. Bump the version in <code>package.json</code>, following the versioning rules on the Governance page:<ul>
<li><strong>Patch:</strong> fixes.</li>
<li><strong>Minor:</strong> new components or tokens.</li>
<li><strong>Major:</strong> renames or removals.</li>
</ul>
</li>
</ol>
<h2>Developers</h2>
<ul>
<li><strong>Tokens:</strong> pull the new version. Nothing to do unless a token was renamed, which is a major version with a migration note.</li>
<li><strong>Components:</strong> the copies in your project are yours. Compare against <code>src/components/ui</code> when the changelog mentions a component you use.</li>
<li><strong>Questions:</strong> comment on the Figma frame, or open a GitHub issue on this repo with the label <code>design-system</code>.</li>
</ul>
