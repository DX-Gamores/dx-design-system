Three rings of ownership

Core is owned by the design-system team. Product teams extend it through review — and good extensions get promoted.

DS teamCoreTokens, primitives, app shell, templates, guidelines.
Product teams + reviewExtendedProduct patterns built only from Core. Good ones get promoted to Core.
Product teamsLocalOne-off compositions inside a product. No review; Core parts only.

Definition of done

Nothing ships until every box is ticked. Three checklists, one release.

Figma
  • All states as variants
  • 100% token-bound — health check 0
  • Description: WHEN · PROPERTIES · A11Y · TOKENS + CODE
  • Visual docs frame
  • Light/Dark × brands × densities
  • Contrast AA
Code
  • Props mirror Figma
  • APG keyboard behaviour, tested
  • Live example on its docs page
  • CI green: parity, axe WCAG 2.2, visual
Docs & release
  • Spec regenerated (npm run build:all)
  • Changelog entry
  • Version bumped per policy
  • Library published

One number for Figma, tokens and code

Read the version like a traffic light.

Majorx.0.0Remove or rename a component, prop, value or token · change keyboard behaviour. The changelog starts with BREAKING + migration.
Minor3.x.0New component, variant, prop, token, mode or icon · deprecations · value changes that keep meaning.
Patch3.0.xFixes and docs · visual tweaks inside existing tokens.

From request to release

Weekly triage. Every step leaves a trace on the Research page or in the changelog. Requests go in as GitHub issues labelled design-system.

  1. 1RequestIssue form: problem, evidence, API, accessibility.
  2. 2TriageAccept, reuse, or decline with a reason.
  3. 3ResearchFindings + sources on the Research page.
  4. 4DesignAll states, tokens only, docs frame.
  5. 5BuildReact mirrors Figma props; tests.
  6. 6ReleaseDone → semver → changelog → publish.

Deprecation: mark, keep, remove

Nothing disappears without warning.

  1. 1MarkPrefix “⚠ Deprecated/”, say what to use; console.warn in code; $deprecated on tokens.
  2. 2KeepAt least one minor release and 30 days.
  3. 3RemoveIn the next major, with a migration note.
